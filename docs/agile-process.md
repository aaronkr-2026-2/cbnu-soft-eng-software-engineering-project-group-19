# Week 5: Lightweight Agile/Scrum retrofit

This is a lightweight process to apply to ongoing work from this milestone onward. It does not claim the project followed Scrum before this retrofit.

## Work tracking

Maintain one prioritized backlog. Track each item as **Backlog**, **Ready**, **In progress**, **Review**, or **Done**. Keep work small enough to review in roughly one to three days. Each item should state the user outcome, acceptance criteria, and any dependency.

## Weekly cadence

- **Planning (20 minutes):** choose a small set of highest-priority items for the week and define a goal.
- **Async check-in (2–5 minutes per workday):** record what changed, the next task, and blockers in the issue or pull request.
- **Review (20 minutes):** run the app, inspect the changes, and compare them with acceptance criteria.
- **Retrospective (10 minutes):** record one thing to continue, one issue to improve, and one action for next week.

For a solo project, keep the same routine as a short personal review. For a team, assign one person to review a change they did not author when possible.

## Definition of Ready

An item has a user or maintenance outcome, bounded scope, acceptance criteria, and known dependencies. If a question blocks implementation, record it before starting.

## Definition of Done

- Code and documentation are saved in the correct repository.
- The change is checked against its acceptance criteria.
- Existing relevant flows are checked manually or with automated tests where available.
- No credentials, local `.env` files, or virtual environments are included.
- The AI collaboration log is updated for AI-assisted work.

## Current process limitation

The supplied project did not include an issue board, sprint history, or review records. This document establishes the process going forward; it is not evidence that those artifacts already exist.
